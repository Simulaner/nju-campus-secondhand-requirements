# 栖物：南京大学校园二手交易平台设计说明

版本：实验2设计稿，2026-11-13。需求基线：`lab1-final`，提交 `18d2c7ed570bb7d92070cba4afeb877da53802e9`。

## 1. 设计目标与范围

普通用户通过南京大学邮箱注册，一个账号兼具买家和卖家身份；管理员审核商品、处理违规、管理账号并查看统计和日志。交易采用线上预约、线下面交、双方确认完成的方式。产品名“栖物”为本次界面设计命名，不代表学校官方产品。

本阶段形成设计模型、页面及交互原型。HTML原型使用本地演示数据；界面中的登录、验证码、角色切换和事务反馈仅用于交互验证，不能当作生产环境的权限、安全或并发实现。

界面以清晰的信息层次和完整的交易流程为目标，界面优先展示当前任务、状态、主要操作，将规则解释与历史放在次级区域。保持实验1排除的在线支付、退款、物流、即时聊天、竞价、推荐算法和复杂纠纷仲裁范围不变。

| D04 重上架 | 主动下架商品可编辑后重新提交审核；违规下架先由管理员解除重审限制，再由卖家重提 | 对REQ-032的设计阶段补充 |
| D05 预约期间修改 | 冻结价格、描述、图片与面交地点等商品信息；允许按既有规则下架并取消预约 | 对REQ-033的设计阶段补充 |

| D08 交易地点 | 建议校内公共地点，发布时选填；不新增必填限制 | REQ-006未明确必填，本次采用不阻断提交的保守设计 |
| D09 停用账号 | 停用前显示影响并要求管理员说明原因；撤销会话，下架其未售公开商品、取消作为买家/卖家的有效预约；保留已完成交易；恢复账号不自动恢复商品 | 工程补充规则；正式实现前需结合业务验收 |
| D10 超时 | 仅待卖家确认状态采用24小时；now>=expiresAt时不能再接受；重启后补扫 | REQ-018及边界工程细化 |
| D11 图片与验证码 | 图片1～9张，单张≤5MB，JPG/PNG/WebP；验证码有效10分钟，60秒可重发，连续5次错误后该验证码失效 | 工程默认参数，可调整；正式实现需限制发送频率、加密传输与安全存储 |
| D12 终止请求 | 终止状态不再变更；合法重复请求可返回原操作结果，不重新写交易或重复通知 | REQ-015、019、034的一致性设计 |

D04～D12是设计阶段对需求边界的补充。联系方式清理、账号停用和默认参数将在正式实现前结合业务验收确认；实验1需求基线保持不变。

## 3. 模块与职责

| 模块 | 核心服务 | 责任 |
| --- | --- | --- |
| 账号与身份 | AuthService、AccountService | 邮箱验证、会话、管理员账号管理、对象归属校验 |
| 商品与搜索 | ProductService、QueryService | 草稿、字段验证、图片、重审、下架、多条件查询与排序 |
| 审核与治理 | ModerationService | 通过/驳回、理由、违规下架、解除重审限制 |
| 预约与交易 | ReservationService | 唯一预约、接受/拒绝、取消、到期、双方完成确认、历史 |
| 通知 | NotificationService | 持久化站内通知、已读状态、业务对象链接 |
| 统计与日志 | ReportingService、AuditService | 按权限汇总数量、关键事件与失败结果的只读审计 |
| 基础设施 | ORM、图片存储、邮件适配器、Clock、ExpiryCommand | 持久化、图片文件、可替换邮件后端、可控时钟及补偿扫描 |

页面/表单负责呈现和基础校验；业务服务负责权限、业务规则与事务边界；数据库负责外键和唯一约束。界面隐藏按钮不能替代服务器鉴权。状态变更复用同一服务，定时任务不另写一套状态规则。

建议实现为Django单体、模板页面和少量JavaScript。SQLite适合课程本地部署；并发写使用短事务、条件更新和唯一约束，不能把SQLite上的`select_for_update()`当作有效行锁。若实测负载不足，再基于证据迁移数据库。

## 4. 数据字典

统一使用UUID标识、UTC持久化时间与北京时间展示。价格以整数分保存，界面展示元；服务端限制精度和最大值，草稿允许字段暂缺，正式提交要求完整。

| 实体 | 主要字段 | 约束和关联 |
| --- | --- | --- |
| User | id、email、passwordHash、displayName、isActive、isAdmin、sessionVersion | 邮箱唯一；普通用户不能赋予管理员身份；密码仅保存哈希 |
| EmailVerification | id、email、codeHash、expiresAt、attempts、sentAt、consumedAt | 验证码一次性使用、期限及频次限制；不得记录明文到审计 |
| Category | id、name、enabled | 名称唯一；草稿可未选分类，提交须关联有效分类 |
| Product | id、sellerId、categoryId、title、description、priceFen、condition、meetingPlace、status、version、relistBlocked、offReason、publishedAt | 卖家外键；公开商品字段有效；版本用于识别旧页面 |
| ProductImage | id、productId、storageKey、position、mimeType、size | 图片归属商品；序号唯一；上传临时文件成功关联后再提交，孤立文件清理 |
| ReviewRecord | id、productId、productVersion、reviewerId、decision、reason、createdAt | 关联被审核版本；同一版本不能重复形成相互冲突的最终审核决定；驳回原因必填 |
| Reservation | id、productId、buyerId、sellerId、status、expiresAt、buyerConfirmedAt、sellerConfirmedAt、productSnapshot、cancelReason、version | 有效状态的productId条件唯一；买卖双方不同；快照不含敏感联系方式 |
| HandoverContact | reservationId、ownerId、kind、value、consentAt | 每条预约每个当事人最多一条；有效且已接受时按归属展示；终止清除 |
| TradeRecord | id、reservationId、completedAt、agreedPriceFen | reservationId唯一；只有双方确认齐全时创建，保留交易历史 |
| RequestReceipt | actorId、requestKey、requestHash、objectId、resultCode、createdAt | actorId+requestKey唯一；同一key不同payload拒绝；未知结果可查询 |
| Notification | id、recipientId、eventKey、objectType、objectId、message、createdAt、readAt | eventKey+recipientId唯一，防重复通知；点击链接再次校验对象权限 |
| AuditLog | id、actorId、objectType、objectId、action、result、reasonCode、occurredAt、correlationId | 系统操作者可空；只读、无删除入口；不含密码、验证码和联系方式 |

数据库结构除外键外，还需要：商品状态/买家查询索引、预约状态与expiresAt联合索引、按操作者或时间检索的日志索引。普通买家可见已发布与已预约商品，不能通过URL、筛选或图片路径泄漏草稿和待审核商品。

## 5. 权限矩阵

| 操作 | 未登录 | 买家 | 商品卖家 | 管理员 |
| --- | --- | --- | --- | --- |
| 浏览公开商品 | 可（工程默认） | 可 | 可 | 可 |
| 注册/登录 | 可 | 登录后无需重复 | 登录后无需重复 | 管理员不开放自注册 |
| 发布/编辑草稿 | 不可 | 普通账号可切换卖家任务 | 仅本人商品且状态允许 | 不代替用户发布 |
| 预约商品 | 不可 | 非本人、已发布商品 | 不可预约自己的商品 | 无管理越权代预约 |
| 接受/拒绝预约 | 不可 | 不可 | 仅自己商品的待确认预约 | 不代确认 |
| 取消预约 | 不可 | 仅本人有效预约 | 通过下架结束商品交易 | 通过违规/账号处理联动结束 |
| 完成确认 | 不可 | 仅本人确认收货 | 仅本人确认完成 | 不代替当事人 |
| 查看联系方式 | 不可 | 已接受有效预约的本人 | 已接受有效预约的本人 | 普通审核界面不展示 |
| 商品审核与违规处理 | 不可 | 不可 | 不可 | 可，检查状态并记录原因 |
| 个人商品/交易历史 | 不可 | 仅本人参与 | 仅本人参与 | 按管理职责查看必要字段 |
| 平台统计/审计/账号停用 | 不可 | 不可 | 不可 | 可；审计无编辑删除功能 |

买卖角色是同一普通账号在具体资源上的身份。实现中以用户ID、资源归属和状态组合判断，不以客户端“切换视角”作为授权依据。

## 6. 状态转换表

| 商品原状态 | 事件 | 新状态 | 关键条件及联动 |
| --- | --- | --- | --- |
| 草稿/已驳回 | 提交审核 | 待审核 | 本人；字段与图片有效；生成唯一待处理版本 |
| 待审核 | 审核通过/驳回 | 已发布/已驳回 | 管理员；版本仍有效；记录审核依据 |
| 已发布 | 修改重要信息 | 待审核 | 本人；同事务阻止并发预约，暂停公开 |
| 已发布 | 预约成功 | 已预约 | 非本人；有效预约唯一；关联状态同成同败 |
| 已预约 | 拒绝/取消/到期 | 已发布 | 正好是该有效预约的占用且未被下架；预约同时终止 |
| 已发布/已预约 | 主动或违规下架 | 已下架 | 预约取消、通知、日志；违规下架设置重审限制 |
| 已下架 | 再次提交审核 | 待审核 | 本人、未限制重审、字段有效；不直接公开 |
| 已预约 | 双方均确认完成 | 已售出 | 已接受预约；唯一交易结果；清理联系信息 |

已售出无恢复或重卖路径。草稿直接售出、待审核直接预约、下架直接发布均禁止。编辑请求与预约竞争时，只有符合实时状态的事务能够成功。

| 预约原状态 | 事件 | 新状态 | 说明 |
| --- | --- | --- | --- |
| 待卖家确认 | 卖家接受 | 已确认待交接 | now<expiresAt；停止待确认超时倒计时 |
| 待卖家确认 | 卖家拒绝 | 已拒绝 | 到期前；商品占用同步释放 |
| 待卖家确认 | 系统到期处理 | 已超时 | now>=expiresAt；重复扫描不重复通知 |
| 待确认/已确认 | 买家取消、商品下架、停用清理 | 已取消 | 原因可追踪，商品根据当前状态处理 |
| 已确认待交接 | 仅一方确认 | 状态不变 | 分别保存双方确认时间；允许重复查询原结果 |
| 已确认待交接 | 双方均确认 | 已完成 | 同事务写预约、商品、交易结果与成功审计 |

已拒绝、已取消、已超时、已完成是终止状态，不再激活。已接受预约不自动使用24小时交接期限。按实验1规则，一方确认后买家仍可在交易正式完成前取消；本期没有资金仲裁功能。

## 7. 事务、不变量与异常

每次业务写操作均按“身份与归属校验→请求幂等校验→事务中读取实时状态→条件更新→相关记录及成功日志/通知→提交”执行。对于锁竞争和写入错误，回滚完整业务，再独立记录失败审计；数据库整体不可用时将失败记录写入项目目录下的受控备用日志，恢复后归档。

不变量包括：每个商品最多一条有效预约；已售出必有关联完成交易；一条预约最多一条交易结果；已下架不可被旧取消/到期任务恢复发布；已接受预约的单方确认不等于完成；成功通知与业务记录一致且不重复。

HTTP超时不能证明服务器失败。界面显示“正在核对结果”，按请求标识查询；只有确认未成功才允许重试同一操作。下架与取消/超时竞争、第二方确认与取消竞争均由统一事务规则决定，不能由界面执行顺序决定。

通知采用站内记录，和业务变更同事务写入。邮箱验证的发送属于外部动作，使用适配器并记录发送结果；测试后端与正式SMTP明确区分。

## 8. UI、信息层次及可访问性

页面层次：商品大厅→商品详情→交易中心/交易详情；我的发布→编辑/审核结果；消息中心；管理员工作台→审核、商品、用户、日志。高频任务在顶部导航，管理端使用稳定侧栏。注册/登录独立展示。

采用1440px桌面画板、约1200px内容区；品牌紫`#6746A4`、正文`#242333`、背景`#F7F7FA`、浅紫`#F0EBF8`。按钮、卡片、标签、提示和表单统一。字号以15～16px正文、20px区块标题、30px页标题为主。图片使用公开照片作为示意，非真实用户上传商品。

列表优先显示图片、名称、价格、新旧程度、状态和地点简写；详情再展示完整描述、规则、卖家及操作。交易页顶部回答当前状态、下一操作者、有效期限，右侧放主要操作，下方为历史。管理员审核展示队列与详情，驳回原因必填。

状态采用文字+颜色，不只用红绿区分。按钮有可见键盘焦点，表单有标签，错误文本与输入关联，成功/错误反馈可被辅助技术识别。原型提供基础窄屏布局；移动端并非本期独立交付目标。

## 10. 验证与实现交接

实验2验证：图源均可本地渲染；图片正常加载；核心界面无横向溢出；原型的搜索、预约、双方确认、审核、下架、重新提交、账号处理和通知能够演示；报告逐页检查。实际运行结果单独保存在process，不提前声称已通过。

实验3需实现真实登录和邮件、服务端权限、持久化、图片安全、事务和并发。重点用例：多人预约同一商品、重复请求、重要修改与预约竞争、到期与接受竞争、下架与超时竞争、双确认与取消竞争、账号停用清理、故障整体回滚。性能目标仍为约100并发、至少95%的全部请求在2秒内成功返回，具体数据量与硬件另定并记录。
